# Модель знань для реалізації системи адаптації динамічних властивостей комп'ютерної гри в процесі виконання фізичних вправ на балансуючих дошках

## Вступ
Модель знань повинна враховувати класифікаційні критерії фізичних вправ та результати класифікації ігор для трьох систем (Wii Fit, PlankPad, BoBo Balance) для динамічного підбору та модифікації вправ під рівень і цілі гравця.

## Розгляд варіантів моделей знань

### 1. Системи, засновані на правилах (Rule-based Systems)
*   **Опис:** Знання представлені у вигляді набору логічних правил типу "ЯКЩО-ТО" (IF-THEN). Наприклад: "ЯКЩО рівень гравця = 'початковий' І ціль тренування = 'стабілізація' ТО рекомендувати вправу = 'Wii Fit: Бульбашка рівноваги'".
*   **Переваги:**
    *   Легкість розуміння, інтерпретації та підтримки для експертів доменної області.
    *   Явне представлення знань.
    *   Прямолінійне застосування до структурованих класифікаційних критеріїв.
*   **Недоліки:**
    *   Можуть стати складними та важкими в управлінні при великій кількості правил та змінних.
    *   Складнощі в обробці неочікуваних ситуацій або нюансованих станів гравця.
    *   Потребує ручного кодування всіх правил.

#### Особливий випадок: Дерева прийняття рішень як представлення правил
Дерева прийняття рішень є візуально зрозумілою та структурованою формою системи правил. Кожен шлях від кореня дерева до листка є еквівалентом одного правила `ЯКЩО-ТОДІ`.

*   **Зв'язок з правилами:** Умови на вузлах шляху формують частину `ЯКЩО`, а результат у листку — частину `ТОДІ`. Наприклад, шлях "Положення = планка" -> "Рух = динамічний" -> "Рекомендувати: Fruit Slicer" відповідає правилу: `ЯКЩО ("Положення" = "планка" І "Рух" = "динамічний") ТОДІ "Рекомендувати: Fruit Slicer"`.

*   **Переваги такого представлення:**
    *   **Структурованість:** На відміну від плоского списку правил, дерево має чітку ієрархію.
    *   **Відсутність конфліктів:** Класичне дерево гарантує, що для одного входу спрацює лише одне правило.
    *   **Автоматична генерація:** Дерева можна "навчити" на даних, що автоматизує створення класифікаційних правил.

*   **Недоліки для динамічної адаптації:**
    *   **Статичність:** Правила, представлені у дереві, є класифікаційними, а не трансформаційними. Вони не призначені для динамічної зміни стану системи (наприклад, підвищення рівня гравця), що є ключовим для адаптації.

Таким чином, дерева рішень слід розглядати як інструмент для **генерації та представлення статичних наборів правил**, але вони не замінюють потреби в більш гнучкому рушії правил для динамічного управління процесом тренування.

### 2. Онтологічні системи (Ontology-based Systems)
*   **Опис:** Знання представлені як формальна, явна специфікація спільної концептуалізації. Вона визначає класи, властивості та відносини між концепціями (наприклад, "Вправа" є типом "Активності", "Вправа" має "РівеньСкладності").
*   **Переваги:**
    *   Забезпечує структуроване та семантичне представлення знань.
    *   Сприяє обміну та повторному використанню знань.
    *   Може підтримувати складніше міркування, ніж прості системи, засновані на правилах.
*   **Недоліки:**
    *   Розробка може бути складною та трудомісткою.
    *   Потребує досвіду в інженерії онтологій.
    *   Міркування можуть бути обчислювально інтенсивними.

### 3. Міркування на основі прецедентів (Case-Based Reasoning - CBR)
*   **Опис:** Вирішує нові проблеми шляхом адаптації рішень, які використовувалися для вирішення подібних минулих проблем (прецедентів). "Прецедент" може складатися з профілю гравця, його ефективності у виконанні вправи та адаптованої рекомендації вправи.
*   **Переваги:**
    *   Навчається на досвіді.
    *   Може обробляти нюансовані ситуації, знаходячи "найближчий" прецедент.
    *   Зменшує потребу в явному кодуванні правил.
*   **Недоліки:**
    *   Потребує великої та добре організованої бази прецедентів.
    *   Визначення метрик подібності може бути складним.
    *   Продуктивність може знижуватися через нерелевантні прецеденти.

### 4. Моделі машинного навчання (Machine Learning Models)
*   **Опис:** Використовує алгоритми для вивчення закономірностей з даних.
    *   **Навчання з підкріпленням (Reinforcement Learning - RL):** Агент навчається приймати рішення, виконуючи дії в середовищі та отримуючи винагороди або штрафи. Тут агент рекомендуватиме вправи, а винагорода ґрунтуватиметься на прогресі/задоволенні гравця.
    *   **Рекомендаційні системи (Recommender Systems):** Пропонують елементи (вправи) користувачам (гравцям) на основі їхніх уподобань, минулої поведінки та схожості з іншими користувачами.
*   **Переваги:**
    *   Можуть адаптуватися динамічно та вивчати складні закономірності.
    *   Можуть ефективно персоналізувати рекомендації.
*   **Недоліки:**
    *   Потребує великих обсягів даних для навчання.
    *   Відсутність інтерпретованості ("чорний ящик").
    *   Проблема "холодного старту" (відсутність даних для нових користувачів/вправ).

### 5. Гібридні моделі (Hybrid Models)
*   **Опис:** Комбінує два або більше підходів, наприклад, систему, засновану на правилах, що керує моделлю машинного навчання, або онтологію, що надає структуру для CBR.
*   **Переваги:**
    *   Може використовувати сильні сторони різних підходів та пом'якшувати їхні недоліки.
*   **Недоліки:**
    *   Підвищена складність у проектуванні та реалізації.

## Критичний аналіз та пропозиція кращої моделі

Враховуючи контекст, система повинна:
*   Розуміти характеристики вправ (на основі `Classification.md`).
*   Розуміти ефективність гравця та адаптуватися.
*   Рекомендувати відповідні вправи.

Наявність структурованих класифікаційних критеріїв з `Classification.md` вказує на моделі, які можуть використовувати явне представлення знань.

**Пропонована найкраща модель: Уточнена гібридна модель**

На основі аналізу, пропонується уточнена гібридна модель, яка поєднує сильні сторони трьох підходів: Онтології, Дерев рішень та загальної Системи правил.

*   **1. Онтологія/Граф знань (Основа знань):**
    *   Центральне сховище, що формально описує всі сутності: вправи, їхні класифікаційні параметри, типи обладнання, профілі гравців тощо.
    *   Забезпечує семантично багате, узгоджене та легко запитуване представлення всієї доменної області.

*   **2. Дерева прийняття рішень (Компонент для класифікації):**
    *   **Особливість:** Цей компонент використовується як ефективний **генератор правил для вирішення статичних завдань класифікації**.
    *   **Основне застосування:** Первинна оцінка гравця. На основі анкети (вік, цілі, досвід) дерево рішень може миттєво визначити початковий рівень складності та рекомендувати стартову категорію вправ.
    *   Це дозволяє автоматизувати створення набору правил для початкового профілювання та розвантажує основний рушій правил.

*   **3. Загальний рушій правил (Компонент для динамічної адаптації):**
    *   Це "мозок" системи, що відповідає за динаміку. Він працює поверх онтології.
    *   Його правила не просто класифікують, а **змінюють стан системи** (наприклад, рівень гравця, його показник втоми).
    *   Приклад правил:
        *   **Трансформаційне правило:** `ЯКЩО Гравець.продуктивність_у(поточна_гра) > 90% ТОДІ збільшити Гравець.рівень_майстерності на 1`.
        *   **Рекомендаційне правило:** `ЯКЩО Гравець.рівень_майстерності = 'просунутий' І Гравець.ціль = 'координація' ТОДІ знайти_в_онтології гру з відповідними параметрами`.

**Чому це найкращий підхід:**

*   **Синергія компонентів:** Модель поєднує швидкість та простоту дерев рішень для початкової класифікації з гнучкістю та потужністю загального рушія правил для динамічної адаптації.
*   **Інтерпретованість та пояснюваність:** Логіка залишається прозорою на всіх рівнях: і в структурі дерева рішень, і в явно прописаних правилах адаптації.
*   **Структуровані знання:** Онтологія слугує єдиним джерелом правди, забезпечуючи узгодженість даних для всіх компонентів системи.
*   **Розширюваність та Керованість:** Додавання нових вправ чи критеріїв вимагає оновлення онтології, а не перебудови всієї логіки. Додавання нових сценаріїв адаптації зводиться до написання нових правил.
*   **Незалежність від великих даних:** Система може стартувати з експертно створеними деревами та правилами, поступово накопичуючи дані для їх майбутнього вдосконалення.

**Як це працюватиме:**

1.  **Ініціалізація:** Система завантажує дані класифікації вправ в Онтологію.
2.  **Початкове профілювання гравця (Дерево рішень):** Користувач відповідає на кілька запитань. Дерево рішень обробляє ці відповіді та визначає стартовий профіль гравця: початковий рівень, рекомендовану ціль тренування тощо. Ці дані записуються в його профіль в Онтології.
3.  **Рекомендація першої вправи (Рушій правил):** На основі створеного профілю, загальний рушій правил робить запит до Онтології та рекомендує першу вправу.
4.  **Моніторинг продуктивності:** Під час вправи система контролює продуктивність гравця (стабільність, точність).
5.  **Динамічна адаптація (Рушій правил):** На основі даних моніторингу, трансформаційні правила оновлюють стан гравця в Онтології (змінюють рівень, фіксують прогрес). Після завершення вправи, рекомендаційні правила підбирають наступне завдання.

Ця гібридна модель забезпечує баланс між явними, інтерпретованими знаннями та адаптивною поведінкою, що робить її дуже придатною для описаного проекту гейміфікації вправ на балансуючій дошці.

## Пропонована структура даних для Бази Знань

Для зберігання гібридної бази знань пропонується структура даних у форматі JSON. Цей формат є гнучким, людиночитаним та легко інтегрується з будь-яким програмним рушієм правил.

Структура складатиметься з двох основних частин:
1.  **Сутності (Entities)**: Опис основних об'єктів системи (вправи, гравець). Це реалізація "Онтології/Графа знань".
2.  **Правила (Rules)**: Набір правил `ЯКЩО-ТОДІ` для реалізації логіки класифікації та адаптації.

### 1. Структура Сутностей (Entities)

Це централізоване сховище всіх об'єктів системи.

#### 1.1. `Exercises` (Вправи)

Масив об'єктів, що описують кожну вправу згідно з вашими класифікаційними критеріями.

```json
[
  {
    "id": "wii_balance_bubble",
    "name": "Бульбашка рівноваги",
    "source": "Wii Fit",
    "classification": {
      "position": "стоячи",
      "movement_type": "динамічний",
      "focus_zone": ["координація", "все тіло"],
      "complexity": 1,
      "goal": "стабілізація"
    }
  },
  {
    "id": "plankpad_fruit_slicer",
    "name": "Fruit Slicer",
    "source": "PlankPad",
    "classification": {
      "position": "планка",
      "movement_type": "динамічний",
      "focus_zone": ["корпус", "плечі"],
      "complexity": 3,
      "goal": "сила"
    }
  }
]
```

#### 1.2. `Player` (Гравець)

Об'єкт, що зберігає всю інформацію про користувача: його профіль, цілі та історію.

```json
{
  "id": "player_001",
  "profile": {
    "goals": ["стабілізація", "зміцнення корпусу"],
    "experience": "початківець",
    "current_levels": {
      "core_strength": 1,
      "leg_strength": 1,
      "balance_skill": 2
    },
    "fatigue_level": 0.1
  },
  "history": [
    {
      "exercise_id": "wii_balance_bubble",
      "timestamp": "2026-01-09T10:00:00Z",
      "performance_score": 92,
      "duration_seconds": 120
    }
  ]
}
```

### 2. Структура Бази Правил (Rule Base)

Це масив об'єктів-правил. Кожне правило має умови (`conditions`) та дії (`actions`). Така структура дозволяє реалізувати як статичну класифікацію, так і динамічну адаптацію.

#### Загальна структура правила:
*   `id`: Унікальний ідентифікатор правила.
*   `description`: Опис того, що робить правило.
*   `type`: Тип правила (`Recommendation` - для поради вправ, `Transformation` - для зміни стану гравця).
*   `priority`: Пріоритет виконання (для вирішення конфліктів).
*   `conditions`: Блок "ЯКЩО". Набір умов, які мають бути істинними.
*   `actions`: Блок "ТОДІ". Набір дій, які виконуються, якщо умови істинні.

#### Приклад 1: Правило для рекомендації (Recommendation Rule)

Це правило знаходить і рекомендує вправу для початківця, який хоче зміцнити кор.

```json
{
  "id": "rec_beginner_core_exercise",
  "description": "Рекомендувати просту вправу на кор для початківця.",
  "type": "Recommendation",
  "priority": 10,
  "conditions": {
    "all": [
      {
        "fact": "player",
        "path": "$.profile.current_levels.core_strength",
        "operator": "lessThanOrEqual",
        "value": 1
      },
      {
        "fact": "player",
        "path": "$.profile.goals",
        "operator": "contains",
        "value": "зміцнення корпусу"
      }
    ]
  },
  "actions": [
    {
      "type": "find_and_recommend_exercise",
      "params": {
        "count": 1,
        "criteria": {
          "all": [
            {
              "fact": "exercise",
              "path": "$.classification.focus_zone",
              "operator": "contains",
              "value": "корпус"
            },
            {
              "fact": "exercise",
              "path": "$.classification.complexity",
              "operator": "equal",
              "value": 1
            }
          ]
        }
      }
    }
  ]
}
```

#### Приклад 2: Правило для адаптації (Transformation Rule)

Це правило підвищує рівень сили кора гравця, якщо він успішно виконав вправу з високою ефективністю.

```json
{
  "id": "tr_increase_core_level",
  "description": "Підвищити рівень 'кор', якщо гравець виконав вправу на кор з ефективністю > 90%.",
  "type": "Transformation",
  "priority": 5,
  "conditions": {
    "all": [
      {
        "fact": "last_event",
        "path": "$.exercise.classification.focus_zone",
        "operator": "contains",
        "value": "корпус"
      },
      {
        "fact": "last_event",
        "path": "$.performance_score",
        "operator": "greaterThan",
        "value": 90
      }
    ]
  },
  "actions": [
    {
      "type": "update_fact",
      "params": {
        "fact": "player",
        "path": "$.profile.current_levels.core_strength",
        "operation": "increment",
        "value": 1
      }
    }
  ]
}
```

### Чому ця структура є ефективною:

*   **Декларативність**: Правила та дані чітко відокремлені від логіки виконання. Ви можете додавати нові вправи чи правила, не змінюючи код програми.
*   **Гнучкість**: Структура умов `fact`, `path`, `operator`, `value` дозволяє створювати запити будь-якої складності.
*   **Масштабованість**: Легко додавати нові класифікаційні параметри, типи правил та дій.
*   **Інтерпретованість**: Правила є людиночитаними, що спрощує їх аналіз та валідацію експертами.

Ця структура даних є міцною основою для побудови запропонованої вами гібридної системи адаптації.
