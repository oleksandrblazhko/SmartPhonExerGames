# Модель GamePlay-Bricks 3.0 для опису механік комп'ютерних ігор

## 1) Механіка "Досягнення" (Achieve), тип "Ціль" (Goal).

### Текстове визначення для старої моделі GamePlay-Bricks 2.0

Механіка пропонує користувачеві підтримувати один або декілька елементів у певному місці або стані рівноваги. 
Наприклад, у грі "Понг" користувач не повинен дозволити м'ячу вийти за межі поля. 
Механіка спонукає користувача розташувати один або декілька елементів у ключових місцях або конфігураціях. 
Наприклад, у грі в пасьянс гравець повинен зуміти розмістити єдину фігуру, що залишилася, в центрі дошки в кінці гри. 
Механіка також спонукає користувача блокувати суперника або визначений елемент. Наприклад, поставити мат королівській фігурі в шахах.

### Текстове визначення моделі GamePlay-Bricks 3.0

Механіка відповідає на питання типу "Якщо...тоді...", яке передбачає зміну стану. 
Це перекладається як пошук збігу між змінними заданого екземпляра та значеннями змінних в іншому екземплярі або списку еталонних значень.
Якщо збіг знайдено, механіка повертає "true" та може діяти як тригер для локальної або глобальної цілі.
Примітка: Avoid є протилежністю механіка Achieve.

### Формалізоване текстове визначення

Нехай Inst = Instance(1)
Нехай Inst2 = Instance(2)
Нехай V = {1 ; … ; v }
Нехай R = {1 ; … ; r }

Inst — поточний екземпляр об'єкту;
Inst2 — другий екземпляр об'єкту;

V — множина змінних стану екземпляру об'єкту Inst;
v — кількість змінних;

R — множина цільових значень;
r — кількість результатів;

Враховуючи, що v = r:

якщо (V(Inst) = R або V(Inst) = V(Inst2)), тоді Achieve = 1

### Datalog-опис
achieve(I) :-
    state(I, S),
    target(S).

achieve(I) :-
    state(I, S),
    state(I2, S),
    I != I2.

## 2) Механіка "Уникнення" (Avoid), тип "Ціль" (Goal).

### Текстове визначення для старої моделі GamePlay-Bricks 2.0

Цей елемент цільового типу спонукає користувача уникати елементів/ перешкод/ ворогів/ супротивників. 
У гоночній грі, такій як Need for Speed, гравець повинен уникати зіткнення з перешкодами своїм транспортним засобом.

### Текстове визначення моделі GamePlay-Bricks 3.0

Механіка перевіряє, чи набір змінних у заданому екземплярі, 
що беруть участь у перевірці локального або глобального збою гри, відрізняється від значень змінних іншого екземпляра або від списку еталонних значень. 
Якщо так, механіка вказує на те, що ціль, яка не мала бути досягнута, досягнута. 
Примітка: Achieve є протилежністю механіки Avoid.

### Формалізоване текстове визначення

Soit Inst = Instance (1)
Soit Inst2 = Instance (2)
Soit V = {1 ; … ; v }
Soit R = {1 ; … ; r }

де Inst — еталонний екземпляр ігрового об’єкта, який береться до розгляду;
де Inst2 — другий екземпляр ігрового об’єкта;
де V — множина змінних, які мають бути досягнуті для екземпляра,
а v — кількість змінних;
де R — множина очікуваних результатів для екземпляра Inst,
а r — кількість результатів;

враховуючи, що кількість змінних v дорівнює кількості результатів r:
Якщо (Inst.V = R або Inst.V = Inst2.R), тоді Avoid = 1

(Поки для кожного екземпляра множина елементів V відповідає множині елементів R
(R може бути включена або не включена до другого екземпляра Inst2),
тоді Avoid повертає значення 1 (істина).)

## 3) Механіка "Створення" (Create), тип "Результати" (Outcomes)

### Текстове визначення моделі GamePlay-Bricks 3.0

Механіка пов'язана з механіками типу Ціль (Goal) або Засоби (Means). 
Якщо пов'язана механіка запитує це, Create генерує потрібні елементи (Екземпляри, змінні та дані).
Примітка: Destroy є протилежністю цеглинці Create.

### Формалізоване текстове визначення

Нехай BG <=> BO або BM або M  
Нехай Inst = Instance (n)  
Нехай V = {1 ; … ; v }  
Нехай D = {1 ; … ; d }  

де BG — механіка Gameplay типу Бри́ка  
типу Ціль (BO) або типу Бри́ка Засіб (BM)  
або типу Метабри́ка (M), пов’язана з Бри́кою  
CREER ;

де Inst — множина з n екземплярів, які потрібно створити;  
де V — множина змінних, пов’язаних з кожним екземпляром n,  
а v — кількість змінних;  
де D — множина даних, які потрібно присвоїти кожній змінній з V,  
а d — кількість даних;

враховуючи, що кількість змінних v дорівнює кількості результатів d:

Якщо (BG == 1) тоді {
Створити Inst  
Створити Inst. V  
V = D  
}

з умовами n > 0, v > 0, d > 0.

(Якщо BG повертає 1 (істина), 
тоді створюється n екземплярів і v змінних, пов’язаних з кожним екземпляром, 
із присвоєнням даних із множини D.)

## 4) Механіка "Руйнування" (Destroy), тип "Результати" (Outcomes)

### Текстове визначення моделі GamePlay-Bricks 3.0

Механіка пов'язана з механіками типу Ціль (Goal) або Засоби (Means). 
Якщо пов'язана Механіка цього вимагає, Destroy видаляє потрібні елементи (екземпляри, змінні та дані).
Примітка: Create є протилежністю цеглинці Destroy.

### Формальне текстове визначення 

Нехай BG <=> BO або BM або M  
Нехай Inst = Instance (n)  
Нехай V = {1 ; … ; v }  

де BG — механіка Gameplay типу Goal-типу (BO) і/або Means-типу (BM)  
або комбінація механік (M), пов’язана з механікою Destroy;

Нехай Inst — множина з n екземплярів, які потрібно видалити;  
де V — множина змінних, пов’язаних з кожним екземпляром n,  
а v — кількість змінних;

враховуючи, що кількість змінних v дорівнює кількості результатів d:

Якщо (BG == 1) тоді {
Видалити Inst  
Видалити Inst.V  
}

з умовами n > 0 і v > 0.

(Якщо BG повертає 1 (істина), тоді видаляється n екземплярів і v змінних, пов’язаних з ними).

## 5) Механіка "Керування" (Manage), тип "Умови" (Conditions)

### Текстове визначення моделі GamePlay-Bricks 3.0

Механіка пов'язана з Механіками типу Засоби (Means).
Перевіряє наявність необхідних ресурсів. 
Якщо умова виконується, Механіка дозволяє запуск пов’язаної цеглинки типу Means, 
інакше — відмовляє у її виконанні.

### Формалізоване текстове визначення

Soit BG <=> BO або BM або M  
Soit Inst = Instance (n)  
Soit V= {1 ; … ; v }  
Soit D = {1 ; … ; d }  

де BG — механіка Gameplay Game-типу (BO) або Means-типу (BM)  
або комбінація механік (M), пов’язана з механікою Manage.

де Inst — множина з n екземплярів, які потрібно створити;  
де V — множина змінних, пов’язаних з кожним екземпляром n,  
а v — кількість змінних;  
де D — множина даних, які потрібно присвоїти кожній змінній з V,  
а d — кількість даних;

враховуючи, що кількість змінних v дорівнює кількості результатів d:

Якщо (BG == 1) тоді {
Створити Inst  
Створити Inst. V  
V = D  
}

з умовами n > 0, v > 0, d > 0.

(Якщо BG повертає 1 (істина), тоді створюється n екземплярів і v змінних, пов’язаних з кожним екземпляром з відповідними даними d)

## 6) Механіка "Вибір" (Select), тип "Засоби" (Means).

### Текстове визначення моделі GamePlay-Bricks 3.0

Зберігає в одній або кількох змінних принаймні одного заданого екземпляра отриманий вибір.

### Формалізоване текстове визначення

Нехай Inst = Instance (n)  
Нехай V(Inst) = {1 ; … ; v }  
Нехай C = {1 ; … ; c }  

де Inst — множина цільових екземплярів;  
де n — кількість екземплярів;  
де V(Inst) — множина змінних v, пов’язаних зі значеннями вибору для Inst;  
де C — множина змінних c, пов’язаних із здійсненими виборами;

Якщо (Select == 1) тоді {
V(Inst) = Select (list, C)
}

де list — список елементів, серед яких необхідно здійснити вибір.

(Якщо вибір зафіксовано, тоді необхідно заповнити кожну змінну множини V(Inst) значеннями вибору C, здійсненими зі списку list.)

7) Механіка "Рух" (Move), тип "Засоби" (Means).

### Текстове визначення моделі GamePlay-Bricks 3.0

Змінює змінну(и), пов'язану(і) з просторово-часовими координатами, обертаннями та швидкостями принаймні одного екземпляра (Переміщення по X (горизонтально), Y (вертикально), Z (глибина), T (час) та R (обертання) з dX, dY, dZ, dT та dR (немає переміщень, які можна вважати еквівалентними швидкості руху)).

### Формалізоване текстове визначення

Нехай Inst = Instance (n)  
Нехай Vx = {1 ; … ; v }  
Нехай Vy = {1 ; … ; v }  
Нехай Vz = {1 ; … ; v }  
Нехай Vt = {1 ; … ; v }  
Нехай Vr = {1 ; … ; v }  

Нехай Inst — множина цільових екземплярів;  
Нехай n відповідає кількості екземплярів;  

Нехай Vx, Vy, Vz, Vt та Vr — множини змінних v, пов’язаних із координатами X (абсциса), Y (ордината), Z (висота), T (час) або R (обертання у просторі) для Inst;

Якщо (DEPLACER == 1) тоді {
Vx (Inst) = Vx(Inst) + dX  
Vy (Inst) = Vy(Inst) + dY  
Vz (Inst) = Vz(Inst) + dZ  
Vt (Inst) = Vt(Inst) + dT  
Vr (Inst) = Vr(Inst) + dR  
}

Нехай dX, dY, dZ, dT та dR — змінні кроку переміщення, що відповідають значенню типу дійсного числа R. 
Чим більший крок, тим більша швидкість.

(Якщо інструкція переміщення за X, Y, Z, T або R зафіксована, 
необхідно збільшити значення dX, dY, dZ, dT або dR для змінних Vx, Vy, Vz, Vt та Vr у межах Inst)

Записує отриману буквено-цифрову послідовність (числа, слова або їх суміші)

Нехай Inst = Instance (n)

V(Inst) = x

9) Механіка "Генератор випадкових значень" (Randomize), тип "Засоби" (Means).

### Текстове визначення моделі GamePlay-Bricks 3.0

Зберігає згенеровані випадкові дані в одній або кількох змінних принаймні одного заданого екземпляра. 
Дані є буквено-цифровими (числа, слова або їх суміш).

### Формалізоване текстове визначення

Нехай Inst = Instance (n)  
Нехай V(Inst) = {1 ; … ; v }  

Нехай Inst — множина цільових екземплярів;  
Нехай n відповідає кількості екземплярів;  
Нехай V(Inst) — множина змінних v, пов’язаних із випадковими даними для Inst;

Якщо (Randomize == 1) тоді {
V(Inst) = випадковий_вибір(list)
}

Нехай list відповідає списку елементів (алфавітно-цифрових даних), серед яких необхідно виконати випадкове вибирання.

(Якщо зафіксовано запит на випадковий вибір, тоді необхідно змінити кожну змінну множини V(Inst), 
присвоївши їй елемент, випадково обраний зі списку list)

10) Механіка "Стріляти" (Shoot), тип "Засоби" (Means).

### Текстове визначення моделі GamePlay-Bricks 3.0

Механіка звертається до механіки Create для створення принаймні одного екземпляра типу "Постріл" з відповідним просторово-часовим зміщенням та швидкістю. Якщо зміщення дорівнює нулю, це постріл упритул, який можна вважати влучанням.
Синоніми до слова "Стріляти": 
- вдаряти;
- стрибати.

### Формалізоване текстове визначення

Нехай CoordDep = {1 ; … ; d }  
Нехай Dir = {1 ; … ; e }  
Нехай QM = {1 ; … ; f }  

Нехай Inst — множина цільових екземплярів;  
Нехай n відповідає кількості екземплярів;  

Нехай CoordDep — множина змінних d, пов’язаних із координатами початку, 
застосованими до Inst, зокрема X (абсциса) або Y (ордината) або Z (висота) або T (час) або R (обертання у просторі);

Нехай Dir — множина змінних e, пов’язаних із напрямком, застосованим до Inst; 
зокрема dirX (напрямок по абсцисі) або dirY (напрямок по ординаті) або dirZ (напрямок по висоті) 
або dirT (напрямок у часі) або dirR (напрямки обертання у просторі);

Нехай QM — множина змінних f, пов’язаних із кількістю руху, застосованою до Inst; 
зокрема M (маса), Vdep (множина швидкостей переміщення у просторі), 
Vtps (множина швидкостей переміщення у часі), Vrot (множина швидкостей, пов’язаних із обертаннями у просторі);

Якщо (Shoot == 1) тоді {
CoordDep (Inst) = listD (d)  
Dir (Inst) = listE (e)  
QM (Inst) = listF (f)  
}

Нехай listD, listE, listF відповідають спискам даних, що вводяться у відповідні множини CoordDep, Dir і QM.

(Якщо зафіксовано запуск пострілу, необхідно заповнити кожну змінну множин CoordDep(Inst), 
Dir(Inst) і QM(Inst) значеннями з відповідних списків listD, listE та listF)

### Datalog-опис
